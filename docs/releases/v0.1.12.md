## Summary

`parakeet-cli` v0.1.12 reports the silence it hears. A session that streams partials now sends a `tick` event on every preview tick with `trailing_silence_ms`, measured with the Silero VAD on the audio as it arrives. A client can end an utterance on real silence instead of guessing a pause from gaps in partial text. Partial and complete output is unchanged, and protocol 2 is unchanged.

Superkeet used gaps in partial text to end a take. With v0.1.11, a three-sentence command with a 742 ms pause split into two takes in 5 of 5 live runs. A Superkeet build that ends takes on `trailing_silence_ms` split it in 0 of 5.

## What's Changed

- A session started with `"partials": true` sends `{"type":"tick","session_id":…,"audio_ms":…,"trailing_silence_ms":…}` about every 0.5 s of captured audio, whether or not the text changed and even while the recognizer is busy. Each tick comes before the partial for the same `audio_ms`, and no tick comes after `transcribing`.
- `trailing_silence_ms` is 0 while the latest 32 ms chunk is speech. Before any speech, it equals the audio heard so far. It counts only whole chunks, so it can lag `audio_ms` by up to 31 ms.
- `transcribe --session --partials` prints the same ticks, so a recording can be checked offline.
- If the silence VAD fails to load or fails during a session, that session sends no more ticks and keeps recording and sending partials. A failed chunk never counts as silence.

## Integration Migration

No change is required. Clients that ignore unknown event types keep working. A client that ends utterances on `trailing_silence_ms` must keep a fallback for a session that sends no ticks or whose ticks stop.

## Validation

- 73 Rust tests pass, including the silence counter, tick order with the preview slot full, the wire shape, and both VAD failure paths
- partial and complete events from the offline replay are identical to v0.1.11
- replaying the three-sentence command at 11 start offsets, the measured silence inside its 742 ms pause peaks at 608 ms, and a tick of at least 900 ms comes 1.0 to 1.5 s after the last word in all 11
- a session with partials loads a second Silero instance, about 17 ms at start, and the VAD costs about 62 µs per 32 ms chunk; a 10 s replay with partials takes about 1.5% longer
