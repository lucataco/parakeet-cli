## Summary

`parakeet-cli` v0.1.10 lets a client record back-to-back sessions without losing the words spoken in between, and lets the daemon clean up after a client that crashed. Protocol 2 is unchanged; both features are opt-in and ignored by older daemons.

## What's Changed

- `stop` accepts `"keep_warm": true`. The capture stream stays open after the session, the newest 3 s of audio is buffered, and the next `start` begins with that audio instead of opening the device again. The microphone closes by itself if no `start` follows within 5 s. `cancel`, capture mode and capture errors never keep it warm.
- A capture thread can now record several sessions in a row. Each session's `dropped_samples` counts only its own losses.
- `serve` reads `PARAKEET_PARENT_PID`. When set, the daemon shuts down (removing its socket and pid file) within about a second of that process exiting, so a crashed or force-quit client no longer leaves the model in memory and the microphone held.

## Integration Migration

No change is required. A client that runs a listening session can send `keep_warm` on the `stop` that ends each utterance except the last, and set `PARAKEET_PARENT_PID` to its own pid when launching `serve`.

## Validation

- 59 Rust tests pass, including the preroll buffer, the `keep_warm` flag and the parent check
- live: with `keep_warm`, "open the notes app" played through the speakers between two sessions, while the client waited 1.2 s to reopen, is transcribed in the second session; without it the second session hears nothing
- live: a daemon whose launching process is killed exits and removes its socket within 1 s

## Build from Source

```bash
git clone --branch v0.1.10 https://github.com/lucataco/parakeet-cli.git
cd parakeet-cli
cargo build --release --locked --bin parakeet
```
