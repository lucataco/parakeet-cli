## Summary

`parakeet-cli` v0.1.7 adds daemon protocol 2: opt-in interim `partial` text while a session is still recording, so a client can act on what is being said before the final transcript. Protocol-1 clients see exactly the protocol-1 event stream. It is the engine used by Superkeet's instant app launch.

## What's Changed

- `parakeet protocol-version` prints `2`; socket replies carry `"protocol_version": 2`
- `start` accepts `"partials": true`; such a session streams `{"type":"partial","session_id":…,"text":…,"sequence":n,"truncated":bool}` roughly every 0.75 s of captured audio once 0.4 s is pending, stopping at `stop`/`cancel`
- partial text is committed-segment tokens plus a fresh decode of the uncommitted tail; the final `complete` text is unchanged byte for byte whether or not partials were requested
- previews travel on a separate single-slot queue, are skipped when the recognizer is busy, never displace a committed segment, and are never counted in `dropped_samples` or `failed_segments`
- the uncommitted tail re-encoded per tick is capped at 15 s (`truncated` reports when older audio was left out)
- every preview decode appends 0.3 s of silence, which removes the invented tail the TDT decoder otherwise produces for audio cut mid-phoneme
- `transcribe --session --partials --format json` replays a file through the same cadence and preview code for deterministic checks
- `Segmenter::preview`, `PreviewCadence`, `Recognizer::preview`, `protocol::partial` and `PartialEmitter` are unit-tested; `capture` mode never streams partials

## Integration Migration

No change is required. To receive interim text, add `"partials": true` to `start` and handle the new event type:

```json
{"command":"start","session_id":"unique-client-session","partials":true}
```

Treat `partial` text as advisory — a partial's last word may change or vanish in the next one — and keep reading the `text` of `complete` as the transcript. Accept `protocol_version` 2 where 1 was required. See [daemon protocol 2](https://github.com/lucataco/parakeet-cli/blob/v0.1.7/docs/session-protocol.md) for the wire contract and examples.

## Validation and Known Limitations

- 54 Rust tests pass, including preview windowing, cadence, partial numbering/deduplication, opt-in command parsing, and the existing framing/completion/conservation cases
- formatting, all-target Clippy, and the release build pass
- replaying `say`-rendered "open the notes app and create a new note" yields partials "Open the notes up" (0.75 s) and "Open the notes app and create a" (1.5 s) before an unchanged `complete`
- a live daemon session with `partials: true` streams partials in order before `transcribing`/`complete`; without the flag the stream is identical to v0.1.6
- interim text is a best-effort decode of an unfinished utterance and is less accurate at its trailing edge than the final transcript; each tick costs roughly 30 ms + 14 ms per second of uncommitted audio on Apple Silicon CPU
